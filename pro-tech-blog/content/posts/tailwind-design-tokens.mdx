If your design system is “whatever Tailwind class I used last time”, it won’t scale. Tokens are the missing layer: a small vocabulary that keeps UI and content consistent without freezing you into a single palette.

This article shows a practical token setup for Tailwind v4 that works for *apps* (components) and *content* (MDX).

---

## Tokens live in CSS

Define semantic variables once (`--background`, `--foreground`, `--accent`) and reference them from Tailwind utilities or arbitrary values in JSX.

```css title="app/globals.css (excerpt)"
:root {
  --background: #fafafa;
  --foreground: #0f172a;
  --accent: #0d9488;
}

.dark {
  --background: #0a0a0b;
  --foreground: #f1f5f9;
  --accent: #2dd4bf;
}
```

## Tailwind v4: bridge tokens into utilities

Tailwind v4 supports token-first thinking. In this codebase we already map CSS vars via `@theme inline`:

```css title="app/globals.css (token bridge)"
@theme inline {
  --color-background: var(--background);
  --color-foreground: var(--foreground);
  --font-sans: var(--font-geist-sans);
  --font-mono: var(--font-geist-mono);
}
```

That lets your “global meaning” live in CSS while Tailwind handles layout/spacing/typography ergonomics.

## Bridge to content

MDX and marketing copy should consume the same tokens—use `text-[var(--muted)]` sparingly and prefer utilities where they exist so refactors stay mechanical.

### Accessibility

When you pick an accent, verify **focus rings** and **link contrast** in both themes. Automated checks catch some issues; manual tab-through catches the rest.

<Callout variant="warning">
  If a color works for body text but fails for small UI labels, promote it to a
  dedicated token (for example `--accent-muted`) instead of diluting the main
  accent.
</Callout>

## A practical token set (small but complete)

You don’t need 40 tokens. You need the ones that prevent inconsistency:

- `--background`, `--foreground`
- `--muted`, `--muted-bg`
- `--border`
- `--card`
- `--accent` (and optionally `--accent-muted`)
- `--code-bg`

## Summary

- Semantic tokens first, palettes second.
- Dark mode is a first-class theme, not an afterthought.
- Content and UI should read from the same variables where possible.
