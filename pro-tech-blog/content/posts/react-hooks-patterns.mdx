Most hooks articles teach syntax. This one teaches *shape*: how to design hooks that stay predictable under change.

By the end, you’ll have a mental model for effects, stable dependencies, and a few battle-tested patterns you can copy-paste without creating time bombs.

---

## The rule that prevents most bugs

> **Effects synchronize with external systems. Events handle user intent.**

When you invert that (put user intent into effects), you get stale closures, double requests, and “why did this run?” debugging sessions.

<StepCard step={1} title="Prefer events. Use effects for sync.">
  If a piece of work should happen because the user clicked, typed, or submitted — do it in an event handler. If it should happen because the component must stay in sync with something outside React (subscriptions, timers, network listeners), do it in an effect.
</StepCard>

## Dependencies tell the truth

`useEffect`, `useMemo`, and `useCallback` should list **everything** they read from the render scope. Silence eslint only when you have a documented, tested reason.

```tsx title="hooks/useWindowWidth.ts"
"use client";

import { useEffect, useState } from "react";

export function useWindowWidth() {
  const [width, setWidth] = useState<number | null>(null);

  useEffect(() => {
    function onResize() {
      setWidth(window.innerWidth);
    }
    onResize();
    window.addEventListener("resize", onResize);
    return () => window.removeEventListener("resize", onResize);
  }, []);

  return width;
}
```

<Callout variant="warning">
  If you *feel* like you need to omit a dependency, first ask: “Am I trying to use an effect like an event?” That’s the most common reason dependency arrays get ‘optimized’ into incorrectness.
</Callout>

## Stale closure: the bug behind “it works on my machine”

This is the classic failure mode:

```tsx title=" Stale closure"
\"use client\";

import { useEffect, useState } from \"react\";

export function CounterLogger() {
  const [count, setCount] = useState(0);

  useEffect(() => {
    const id = setInterval(() => {
      // Logs the count from the render that created this interval.
      console.log(count);
    }, 1000);
    return () => clearInterval(id);
  }, []); // looks \"stable\" but isn't

  return (
    <button onClick={() => setCount((c) => c + 1)}>Count: {count}</button>
  );
}
```

Fix it by moving changing values out of the closure (functional update) or rebuilding the subscription when needed:

```tsx title=" Fix: functional update"
\"use client\";

import { useEffect, useState } from \"react\";

export function CounterLogger() {
  const [count, setCount] = useState(0);

  useEffect(() => {
    const id = setInterval(() => {
      setCount((c) => {
        console.log(c);
        return c;
      });
    }, 1000);
    return () => clearInterval(id);
  }, []);

  return (
    <button onClick={() => setCount((c) => c + 1)}>Count: {count}</button>
  );
}
```

## Custom hooks are module boundaries

Reach for a custom hook when the same three lines of stateful glue appear twice—not when you want a shorter file.

### Effects and events

Prefer event handlers for user-driven work. Reserve effects for synchronizing with **external systems**: network, storage, subscriptions, non-React widgets.

<StepCard step={2} title="A hook is a boundary, not a helper">
  A good hook hides details behind a name that describes *why* it exists. If you can’t name it without mentioning implementation (e.g. <code>useFetchWithAbortAndRetry</code>), it’s probably two hooks.
</StepCard>

## A scalable pattern: state + actions

As apps grow, you’ll want hooks to return *both* data and stable actions.

```tsx title=" Pattern: return state + actions"
\"use client\";

import { useCallback, useMemo, useState } from \"react\";

export function useToggle(initial = false) {
  const [on, setOn] = useState(initial);

  const setTrue = useCallback(() => setOn(true), []);
  const setFalse = useCallback(() => setOn(false), []);
  const toggle = useCallback(() => setOn((v) => !v), []);

  return useMemo(
    () => ({ on, setTrue, setFalse, toggle }),
    [on, setTrue, setFalse, toggle],
  );
}
```

<Callout variant="tip">
  Returning stable actions reduces prop drilling churn. When your UI grows, “stable actions” becomes a performance tool and a readability tool.
</Callout>

## Mental model

Hooks encode **lifecycle + state** in function form. If a hook becomes hard to name, split it: one hook, one story.
